# 会议纪要预览验收

本轮实现 `meeting-v3` 与 `meeting-baseline`，保持新录音默认 `legacy`。**质量门槛尚未通过。** 本页区分已完成的工程检查、真实调用结果与未完成的实验，不将可运行、合法引用或检查数量称为准确率。

## 固定条件

- 私有录音复用完整版 Large-v3 的同一份原稿：21 分 41.921 秒、1,042 段、6,120 字符。本轮不重跑 ASR 或分人。
- 使用原有积算平台 `deepseek-v4.1-flash`，思考强度保持“高”。输出预算按既有规则从 32K 必要时一次扩至 128K，不自动降强度。
- A 为同样详细程度的全文会议模板基线；B 冻结 `dialogue-reader-v2.0 / dialogue-prompts-v2.4`；C 为新会议工作流。C 的修订前后分别保留，不能把增加篇幅的收益全算给核验。
- 原录音的固定清单包含 33 项信息保留、5 项禁止错误；原稿为机器转录而非人工听写真值。B 使用本轮修改前已完成的应用内结果，其代码与成果哈希已冻结。
- VCSum 116：3,406 字符、52 段，11 项信息保留、3 项禁止错误。其两种标签包含多位嘉宾，不能作为真实二人分人评估。
- VCSum 208：44,043 字符、214 段，所有声音归属设为未确定；26 项信息保留、3 项禁止错误。检查长文与跨段关系。
- VCSum 120 保留既有失败回归，并在新流程运行前冻结 11 项检查。公开样本的时间坐标只是序号，没有配套音频，不用于声学、时长或回听评价。

所有清单在相应新流程输出前冻结，不将公开参考摘要放入生成输入。真实付费调用通过 `/Applications/VideoDHelper.app` 点击启动；公开文本以明确标识的测试任务准备输入，并非新增了面向用户的文本导入功能。离线脚本只检查产物、汇总账本和读取评阅结论。

语义评阅由 Codex 逐项对照固定原文与清单完成，不是独立人工标注或生成模型的自我评分。私有原稿、清单、响应和逐项理由保留本机，公开报告只汇总结果与匿名错误类别。

## 真实运行促成的修复

1. build 18 保留最近 12 份校验失败候选与具体错误，避免只剩“格式不正确”而无法定位。诊断不保存凭据或思考正文。
2. 116 的首次草稿复制引文时遗漏一个字，引发整份重试。build 19 改为选择原文片段编号，由程序取得精确引文；不做模糊匹配或悄悄改写原文。
3. 固定分批核验的声明责任范围，补丁改变引用位置后不会重新分派给后面的批次。
4. 定向回读只允许修改登记问题关联的声明；相邻来源用于理解，不赋予修改其他声明的权限。
5. 标点插入检查跨批次边界，不能在数字或英文标识符内部插入标点。

协议变化使用不同的检查点身份。build 18 的探索结果不混充 build 19 的同版本重复实验，也不复制成功模型响应作为新的收费对照。
