# 0.5 总结流程

实现入口为 `backend/summary.py`，新版阅读器为 `backend/summary_v2.py`。沿用现有 Chat Completions 服务和模型，不需要新增向量服务或 Agent 框架。调研依据见 [研究记录](summarization-research-2026-10-25.md)。

## 输入与阅读

字幕原文不可变。传给模型的是 `[p编号] 文字`，本机另存原字幕编号、起止时间。运输用的小段通常为 240–480 字；单个超长字幕可分片，但每片仍指回同一个原始字幕。小段不是总结章节：短稿一次读完，长稿规划时也尽量一起读完。

默认估计原稿不超过 6,000 工作 Tokens 时走整体阅读；长稿先返回章节边界、主题、术语、前后修正/比较/前提关系，然后按自然主题生成知识点和精简台词。所有章节合起来必须按顺序覆盖每个原文小段。章节执行输入有预算，超长的自然章节可以拆成执行批次，最终仍归同一章。

工作估计为非 ASCII 字符 × 1.5 + ASCII 字符 / 3，整个请求默认预算 48,000。这是保守调度估计，不是该模型的 tokenizer 或正式上下文上限。若全文结构仍超预算或模型明确返回超限，则拆读局部结构，再合成全局结构；后续核验仍访问完整原文，不只访问压缩摘要。

## 核验与定向回读

先让原稿的每一段进入遗漏检查，再对笔记中的具体声明核对证据。若一条声明引用前后相隔很远的段落，核验必须带齐这些引用，防止把“当前窗口没看到”误判成“原稿没有”。核验窗口之外的补充来源用于解释条件和修正；新增遗漏仅处理当前负责的范围。

模型只能提出本视频内的段落编号或字面检索词，程序提供命中段落及邻近段落。它不能执行命令、读取任意文件、访问外部网页或改变处理配置。跨章修正关系也进入回读队列，共用来源的问题合并处理。最多两轮、六次回读，保留未解决问题，不无限循环。

短稿将概览、关键点与正文一起作为待核对声明，只返回修改项；不会为核验重新抄写整份概览。长稿在回读后从完整章节与核验发现生成概览，合并已解决或重复的疑问，再回查概览所用原文。

来源合法和段落覆盖是程序可验证的；语义完整、作者归属、比较方向和识别错字只能辅助检查。“核验已读 45/45 段”不代表语义零遗漏，也不是独立事实核查。详细过程保存在 `review-report.json`。核验疑问另有解决记录；未解决项不能因概览篇幅短而消失。定向回读后仍然存在的原文歧义受程序保护，概览不能通过改写已有笔记将它关闭。

## 恢复、计量与旧流程

- 检查点身份包含模型、接口、推理强度、流程版本、提示词、输入和输出预算。密钥不进入身份或任务文件。
- 模型只在 JSON 结构、来源编号及范围检查通过后写入成功检查点。修改模型或相关提示词会自然失效相应缓存。
- 已出现的上下文/输出超限另外记录；恢复时不再为同一个过小预算付费。截断内容永远不成为成功笔记。
- 完成的章节、核验与回读均可复用。取消中的在途请求可能已由服务商处理；没有响应时用量为未知，不能宣称免费。
- 默认每次运行最多 80 个 HTTP 请求。高 / 最高思考强度达到 1,000,000 个已报告 Tokens 或经过 7,200 秒后停止新增请求；其他强度为 500,000 Tokens / 1,800 秒。已完成结果保留，用户可以继续；已发出的请求可让最终用量超过门槛，这不是严格的账单上限。
- 费用仍使用用户为该模型填写的输入、缓存和输出价格；未知价格或缓存信息不推断为零。检查点命中不等于供应商的 Prompt Cache 命中。
- 用量明细与 CSV 增加“全文结构 / 主题章节 / 遗漏与依据核验 / 定向回读 / 最终概览”等阶段。

旧任务没有 `summaryStrategy` 时按旧流程恢复。新任务默认 `structured`；`legacy` 保留旧流程。开发基准另有 `compact`，仅用于隔离运输格式改动，不在普通设置中提供。对照操作新建任务并复用原稿，不覆盖原任务，也不重新下载或转录。

## 复测

`scripts/benchmark-summary.py` 复用本机三份固定原稿，每个策略输出到独立目录；SIGTERM 会保存本次运行记录，重新执行可继续。真实请求计入正常用量台账。模型配置只在进程内读取，不写到基准目录。

```sh
.venv/bin/python scripts/benchmark-summary.py --strategy structured --output local-data/validation/my-run
.venv/bin/python scripts/benchmark-summary.py --strategy legacy --output local-data/validation/my-baseline
```

质量清单在 `docs/research-data/summary-quality-rubric-0.5.json`。其中关键词只是定位工具，不是自动语义评分。详见 [验收记录](validation-0.5.md)。
