# 录音质量复盘与下一阶段改进计划

日期：2026-10-28。基线：0.7.0 构建 14，应用代码 `988c390`，文档基线 `d6b005b`。本轮只复查现有结果、代码及公开研究，没有新跑转录、调用付费模型或修改应用。以下方案尚未实现。

后续进展：build 15 已完成[三模型管理与接入](validation-asr-manager.md)。进一步调研后，文字理解的实施选择收敛为[全文优先、成果分离、原文核验与有限回读](dialogue-understanding-design-2026-10-28.md)；独立全量事实表降为必要时的对照候选。本页保留当时复盘及实验背景，不表示拟议架构已开发。

## 判断：流程可用，内容质量尚未达到成品目标

原稿保留、来源追踪、用量计量、中断恢复和本机应用交付已经形成基础。但真实普通话录音仍有碎句、归属边界不稳定、含混词过度解释、重要条件遗漏和疑问重复。当前适合预览与回听校订，尚不足以作为高质量对话整理功能发布。

此前的[总结调研](summarization-research-2026-10-25.md)已经提出人工事实清单、固定输入对照和“编号覆盖不等于语义覆盖”。录音适配时，工程完整性验证推进较快，对话专用表示和语义验收没有充分落实。这是本轮应修正的工作方法，而不只是继续加提示词或推理预算。

本次对照来自一段约 22 分钟的真实录音。没有人工逐字听写及说话人参考，不能报告真人 CER、DER、识别准确率或语义召回率。复查发现的是输出与现有机器来源之间的问题；音频本身说了什么，仍须回听确认。

## 1. 可复核的问题

字符以保存的正文 `len(text)` 计，包括原有标点、空格，不含界面标签、Markdown标题。聚合结果见[离线统计](research-data/recording-quality-audit-2026-10-28.json)。私人原稿、错误实例和复算脚本保留在忽略目录中。

| 层次 | 段数 | 正文字符 | 每段字符中位数 | 不超过 2 字的段数 |
| --- | ---: | ---: | ---: | ---: |
| 原始 ASR | 784 | 6,144 | 7 | 38 |
| 分配说话人后的原稿 | 1,060 | 6,139 | 5 | 269 |
| 模型阅读段落 | 504 | 6,139 | 4 | 172 |
| 低强度整理稿 | 496 | 6,385 | 5 | 158 |
| 高强度整理稿 | 496 | 6,361 | 4 | 162 |

分人后段数增加 35.2%。495 次标签切换只有 26 次为直接 A/B 切换，另有 162 个单独 unknown 片段夹在同一确定说话人的前后片段中。这提示边界策略有问题，**不代表可以不听音频就把这些 unknown 强行归给相邻说话人**。

问题链条可在代码中核实：

1. [SpeakerHelper](../Sources/SpeakerHelper/RecordingDiarize.swift) 关闭了 `useExclusiveReconciliation`。
2. [speaker_at / align_speakers](../backend/recording.py) 对一个词只要与两人时间段都有交集就标 unknown，再随每次标签变化切段，没有跨 ASR 段重建完整句子。
3. [paragraphs](../backend/summary_v2.py) 再按 A/B/unknown 的每次变化断开阅读段落。
4. 整理稿要求覆盖所有片段且不能跨标签；含混的单字被保留下来。总结有时把这种算法切分解释成实际的接话事件。

6,139 字符正文经编号、说话人标签、空格和换行序列化后为 17,536 字符。当前工作估算从 8,886 增至 12,685 Tokens；这是调度公式估计，不是服务商 tokenizer 或账单值。

还核实了以下内容问题，公开文档不复述私人对话：

- 有一条原稿明确表达的执行前提，被高强度正文遗漏，引用列表却包含该来源；低强度保留了它。这直接说明引用全覆盖不等于事实完整。
- 高强度把机器原稿中的含混词解释成确定说法，来源不足以支持；不能据此断定原音频到底说了哪个词。
- 19 条高强度待确认中存在同源问题重复，以及对“是否存在矛盾”的判断不一致；还残留回读工作描述。
- 高强度 8 条关键点的最晚来源只到约 15 分钟，而录音还有约 6 分钟。后段具体下一步在章节中保留，却未进入关键点。需要评价信息选择，不能强制每个时间区间都占同样篇幅。
- 高强度正文声明、概览、关键点和待确认合计 7,368 字符，超过 6,139 字符源稿；整理稿也更长。内容长度本身不决定好坏，但结合碎行、重复和缺乏压缩，尚未实现便于阅读的目标。

两档也有共同优点：主要主题可定位，部分条件与未来承诺得到保留，原稿与来源仍可追查。高强度没有稳定全面胜过低强度，修正数量更多不能证明准确率更高。

## 2. 当前到底用了哪些模型，为什么这样选

| 层次 | 当前选择 | 已有依据与证据缺口 |
| --- | --- | --- |
| 语音转文字 | MLX Whisper Large-v3 Turbo / Small | 已有权重可复用、Metal 加速、集成与体积较合适；没有真人中文标注集证明它们最优。Small 是轻量备选 |
| 说话人分析 | SpeakerKit 的 Pyannote / Community-1 Core ML 路径 | macOS 集成与模型分发可行；本机分割用 CPU、嵌入用 CPU/ANE、聚类用 CPU，不是全程 ANE |
| 整理、总结、核验 | 用户指定平台的 `deepseek-v4.1-flash` | 服务已接通、支持配置强度；选用原因是用户提供的可用服务，未经跨模型质量排名 |
| 独立质量评估 | 尚未建立 | high / low 是同一模型的参数档位；当前核验仍由生成模型完成，不是两个独立评估模型 |

首批 ASR 对照只保留三组，以便控制变量：

| 候选 | 实验目的 | Mac 路径与需要验证的内容 |
| --- | --- | --- |
| 当前 Turbo | 冻结速度与质量基线 | 现有 MLX/Metal；不更改原参数以保持对照 |
| Whisper Large-v3 | 检查同家族完整版的质量收益 | MLX Whisper；实测内存、速度、词级时间戳与模型下载成本 |
| Qwen3-ASR 1.7B + ForcedAligner 0.6B | 检验另一模型家族的中文识别与对齐 | MLX Audio 已提供实现及公开量化权重；分别验证量化、长音频窗口、对齐、峰值内存和恢复 |

Turbo 从 Large-v3 裁减解码层以提升速度，官方模型卡说明存在质量取舍；不能从模型大小直接推断这段录音的胜负。[Turbo 模型卡](https://huggingface.co/openai/whisper-large-v3-turbo)

Qwen3-ASR 原项目及模型为 Apache-2.0，MLX 是社区实现，应固定版本并实测。强制对齐只能确定文本的时间位置，不能证明文本正确；官方 aligner 的片段范围不适合直接输入整段 50 分钟录音。[官方项目](https://github.com/QwenLM/Qwen3-ASR)、[本次核实的 MLX 实现](https://github.com/Blaizzy/mlx-audio/blob/6ce7283be6f15f0cba37e839e73bfa4a08bbf040/mlx_audio/stt/models/qwen3_asr/README.md)

SenseVoiceSmall / Paraformer 列为第二批中文与速度候选：已有 FluidAudio 的 Core ML 路径。公开 SenseVoiceSmall 支持中、粤、英、日、韩，不能把全系列的语言数当成 Small 权重能力；代码与权重许可也需分别记录。[SenseVoice 官方说明](https://github.com/QwenAudio/SenseVoice)、[FluidAudio 模型目录](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Models.md)

说话人优先比较当前归属策略、exclusive 辅助归属及话轮重建，再考虑 SpeakerKit 与 FluidAudio Offline VBx。两者都基于 Community-1，主要是实现与聚类对照，不能称为两个独立基础模型。保留真实重叠轨，exclusive 只作为对齐辅助，避免为了降低 unknown 而错误指认说话人。[SpeakerKit](https://github.com/argmaxinc/argmax-oss-swift#speakerkit)、[Community-1 的 exclusive 说明](https://huggingface.co/pyannote/speaker-diarization-community-1)、[FluidAudio 离线分人](https://github.com/FluidInference/FluidAudio#offline-speaker-diarization-pipeline)

## 3. 当前总结架构及其局限

实际路径：**原稿 → 带来源与说话人的阅读段落 → 全文规划 → 分章整理 → 原文覆盖核验 → 定向回读 → 综合概览 → 终检**。

它是预定义、可恢复的工作流，允许模型有限申请读取原文。回读按编号或字面关键词取附近文本，不会回听音频或核实外部事实。当前模型、思考强度在各阶段相同。

原稿估算不超过 6,000 Tokens 才整体阅读；否则规划通常要求 4–14 章，再按章输出声明和整理稿。该阈值是实现选择，不是平台上下文上限。本样本正文约 6,000 字符，即使去掉标签也超过这个估算阈值；不能因为录音时长较长就称为模型意义上的超长文本。

低强度本样本有 25 个成功阶段：1 规划 + 13 章节 + 3 核验 + 6 回读 + 1 综合 + 1 终检。高强度还经历拆分与输出预算失败。单次恢复耗时、请求数不能当作从零开始的处理性能；此前累计 64 次开发请求也不是正常单任务成本。

需要保留来源映射、原始稿、成功检查点与诚实计量。需要改变的部分是：

- 对话仍沿用视频章节结构及全覆盖整理约束，提示词替换和追加规则不足以表示问答、提议、拒绝、条件及明确确认。
- 原稿、整理稿、主题总结承担不同用途；不能要求三者都逐碎片复述全部内容。
- 全局地图、引用和格式重复膨胀输入；需要比较其实际质量收益。
- 回读从已生成地图提出问题，可能继承错误假设；问题应中性，读取完整问答和条件，而非仅盯着原猜测。
- 同模型核验有帮助，却缺少独立校准；更多推理不能自动补足错误 ASR、缺失的音频证据或错误的说话人边界。
- 未解决歧义应保留，但应按稳定问题身份、证据、类型与状态合并，不能只按文字完全相同去重。

128K 是核验输出上限；一次实际 22,504 输出成功、之前 32K 耗尽，说明生成有波动。当前证据只证明高预算让该次请求产出了正文，没有证明提高整体质量。

## 5. 拟议架构

**不可变音频与词级原稿 → 可校订的自然话轮 → 全文理解与证据表 → 整理稿 / 对话总结分别生成 → 风险核验 → 成品清理**。

### 话轮与证据

- 保留原词、时间、重叠轨、人工修改和来源映射；新话轮是派生层，不覆盖原始 ASR。
- 综合停顿、句子边界和声学证据重建话轮。局部归属不清保留局部标记，不把 unknown 当第三位参与者，也不由 LLM 根据措辞猜人。
- 对实质内容建立轻量事实记录：说话人、命题、提问/提议/答复/决定、条件与否定、是否明确确认/撤回、证据与不确定状态。短应答可以是确认的重要证据，不能一律当填充词删除。
- 不为每个字建立事实节点。证据表自身也可能出错，后续核验仍可读取原文，不能让它成为唯一真相。
- 原稿完整留档；整理稿保留问答次序与原话语气，删除重复；总结按实际主题呈现双方观点、问答、共识/分歧、明确下一步和待确认事项，没有就不凑条目。

### 按真实输入规模选择路径

- **能容纳且经过质量测试的文本**：全文阅读，给输出和推理预留容量，按具体风险核验。当前录音必须加入这一对照。
- **超过可靠阅读预算的文本**：按自然话轮/主题分批提取相同证据表，维护跨段指代、条件、更正和未答问题，再全局组织。摘要不是下一阶段唯一输入，原文随时可回读。
- 优先使用匹配 tokenizer；没有时用真实 API usage 校准估计，记录误差和安全余量。上下文能力未知时不按模型名字猜 128K 等上限。
- 风险核验优先查人物归属、否定、数字、条件、共识和撤回；问题中性。需要音频确认的事项明确交给回听，文字回读不能冒充听音。
- 按证据和问题类型合并疑点，内部预算/调度说明保留在诊断区；成品只展示清晰的待回听事项。
- 保留当前模型管理、用量、价格、取消与恢复机制；新策略单独版本化、另存对照结果，不覆盖旧成果。暂不引入向量数据库或通用多 Agent 框架。

## 6. 下一步执行顺序与验收门槛

所有数值门槛均为拟定目标，不是本轮已经取得的成绩。质量优先；两个方案质量相当时，再比较速度、资源与费用。

| 顺序 | 工作与对照 | 完成依据 |
| --- | --- | --- |
| P0-A | 冻结构建14基线；选取合计约6–10分钟、覆盖开中尾/术语/短答/打断/条件的片段，人工听写并标注说话人；建立全录音30–50条关键事实及关系参考 | 每条可定位音频；不清楚的声音如实标注。划分开发与保留测试片段，避免对同一段反复调参后宣称泛化 |
| P0-B | 固定ASR，比较当前归属、exclusive辅助归属、话轮重建 | 检查短碎行、错误归属、漏句与重叠；减少碎片同时不增加关键错误，不能仅以unknown下降验收 |
| P0-C | 同一参考片段比较Turbo / Large-v3 / Qwen3-ASR；固定其他条件，术语提示作为单独实验 | CER、专业词/数字/否定错误、漏句和幻觉；记录量化、峰值内存、Metal/ANE路径、冷/热启动与恢复。CER归一化、DER容差和重叠计分口径公开 |
| P1 | 固定转录、模型、强度和相近成品长度，比较下表架构 | 事实忠实、关键事实召回、条件/归属/共识错误、重复、可读性；重要比较重复至少3次并报告波动，不只挑最好一稿 |
| P2 | 对入围架构比较low/high及账号实际可用的其他模型；必要时另一个模型家族辅助盲评 | 独立评分器先与人工判定校准；模型不能自己给自己签发合格证。无需先新增付费服务 |
| P3 | 追加5–10、20–30、40–50分钟不同真人对话，覆盖解码/转录/总结/中断恢复 | 单样本修复有可重复收益；未获得新样本前只声明本样本结果。通过后更新本地预览与PR，仍等待明确合并再发行 |

总结架构消融组：

| 组 | 方案 | 要回答的问题 |
| --- | --- | --- |
| A | 当前碎片输入与工作流 | 固定历史基线 |
