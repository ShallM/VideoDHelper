# 任务理解 · 开发预览

build 34 新增 `meeting-v4`，从“新建对照任务 → 任务理解 · 预览”使用。原 `meeting-v3` 以“会议纪要 · 上一版”保留，其他历史流程不变；新录音默认仍为 legacy，单个样本不能代替默认切换门槛。

## 使用

先取得录音原稿，再创建独立对照。点击“补充背景与关注点”，可描述录音背景、自己的角色及希望弄清的问题，最多 4000 字符。保存不调用模型；点击“整理与总结”才使用当前云模型，并将文字与背景发送给该服务。

背景只属于当前任务，会随支持它的对照流程复制，不改变全局设置。改变背景会使已有总结标为需重新生成，旧成果仍保留，原稿与说话人结果不修改。旧版 legacy/context-v2 不使用背景，创建这两类对照时明确提示。导出纪要分别展示用户背景与录音内容。

## 三阶段

1. 阅读原稿，形成紧凑信息底稿：核心事项、条件、状态、执行依赖及未决关系。复用“正文＋来源”结构，不增设实体表或知识图谱。
2. 同时读取完整原稿与候选底稿，生成按主题连贯组织的报告。明确行动与分析后建议追问的问题分开；第一阶段不是唯一的信息入口。
3. 对照全文双向核验支持与遗漏，特别检查同一资源/动作跨章节的状态及必要条件。继续使用字段补丁、来源验证和有界回读，不额外整篇润色。

全文有明确重复用法支持时，允许在报告中归一化明显误识别的专业术语，要求记录原字与依据；原稿及引用逐字不变。含混人物、制度、数字与关键语句仍需保留不确定性，不能凭常识补全。

旧会议纪要维持“草稿 → 独立证据 → 核验”。两组仅在用户填写背景时追加同一背景输入规则；无背景的旧流程提示词及检查点身份保持兼容。新流程复用原成果协议、长文责任范围、用量统计、费用、导出和恢复。

任务背景进入检查点身份与成果快照，改变背景、原稿、模型或思考参数不会复用不兼容阶段。成功的信息底稿可在中断后复用。正式验收前完成模拟恢复与长文分层检查；真实对照按[build 34 固定计划](meeting-build34-plan.md)进行，不把来源合法或调用完成称为内容正确。

本次改动来自同一机器原稿的成品复盘：更好的另一会话成品具有额外用户背景，且曾阅读既有验收记录，不是盲测。本实现没有引入多 agent 框架。

同背景 DeepSeek 单轮对照已完成，两组均成功。新流程在执行依赖与表达上有局部改善，但重要内容完整保留 21/30，上一版为 22/30，整体质量门槛未通过；保持可选预览与旧默认，详见[验收结果](validation-meeting-v4.md)。
