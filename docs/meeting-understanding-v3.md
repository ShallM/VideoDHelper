# 会议纪要工作流 · 开发预览

本轮在现有录音工作区增加 `meeting-v3` 与 `meeting-baseline`，保留 `context-v2` 和旧流程。当前新任务默认仍为旧流程，质量门槛通过后才切换；实现完成和离线测试通过不代表语义质量已经提高。

## 依据与取舍

- [Omi 的受限纪要 agent](https://github.com/BasedHardware/omi/blob/f60de9b011ec70cfcab05fde0a6c2669a652ab02/backend/utils/llm/notes_agent.py)：借鉴结构化提交、明确停止规则、查询复用与分类核验；不引入其日历、屏幕或联系人服务。
- [Omi 纪要规则](https://github.com/BasedHardware/omi/blob/f60de9b011ec70cfcab05fde0a6c2669a652ab02/backend/utils/llm/notes_agent_prompt.py)：明确区分提议、决定、意图和已完成事项。规则仍需验证，不视为事实正确的证明。
- [Meetily 全文/分层实现](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/summary/processor.rs)与 [Anarlog 全文增强](https://github.com/fastrepl/anarlog/blob/48a15bb2b0fc671215f55bee5d7ee2dafaf7a7ff/apps/desktop/src/store/zustand/ai-task/task-configs/enhance-workflow.ts)：建立简单全文会议模板基线，检验额外阶段的收益。
- [ExplainMeetSum](https://aclanthology.org/2023.acl-long.731/)：分别评价摘要与支持证据。引用存在不能代替语义支持检查。

本项目采用这些设计原则重新实现兼容现有系统的工作流，不声称复现了这些产品全部后端或其质量成绩。

## 处理链

1. 全文生成约 200 字概览、详细主题纪要、独立行动项及真实疑点，不用固定压缩比例删除重要信息。
2. 新请求只读取原文，独立提取重要事实、状态、条件及原文引文；不包含纪要草稿。
3. 对照原文、证据清单及草稿，检查遗漏、无依据陈述、状态/范围变化、归属及重复，提交局部补丁。
4. 只有能够取得该疑点核验时尚未提供的原文上下文，才定向回读，最多两轮、六个不同问题。短稿全文核验后不重复读取同一份全文，未解决问题照常保留。问题由目标和字段定位；问题文案变化不生成新身份，回读不能登记新问题。只允许修改该疑点关联的声明，邻近原文只供理解，不扩大修改权限。输出按目标与字段使用登记后的问题和状态，避免原疑点与回读问题重复展示；不同字段独立保留，原问题保存在诊断及成果的补充字段中。
5. 程序呈现声明的状态、前提、范围、归属、行动负责人和期限，直接发布，最后不再整篇润色。

`meeting-baseline` 使用相同的草稿及整理稿合同，但跳过独立证据、核验和回读，作为可运行的简单基线。它没有核验结果，界面不冒称已检查。

build 28 将纪要与可选标点优化分开：纪要成功后立即发布，同时提供程序按阅读单元排版的原话。需要更细的断句与标点时，在“整理对话”点“优化断句与标点”，只执行标点阶段，使用当前模型设置并单独计入用量。失败或取消保留纪要和原有整理稿；继续只复用该操作兼容的成功检查点，不重新生成纪要。

能放入请求预算的材料全文处理；确实输入超限时才按完整阅读单元分层。局部候选保留结构化状态与逐字证据，全局核验仍可访问原文。跨段证据无法放入容量时停止并保存成功阶段，不静默删减。

## 来源与状态合同

普通声明只要求正文和来源，类型、状态、条件、范围及说话人依据按实际需要填写，避免反复生成空字段。行动、提议和决定仍须明确状态；未给出的负责人和期限保持空值，普通条目不自动标为待完成。内部归一化后继续兼容既有成果读取和渲染。模型只选择原文单元内连续的片段编号，程序从不可变原文提取引文和字符位置，避免复制引文时漏字导致整次重试。旧诊断中的文字引文仍要求唯一、连续、逐字匹配，不做简繁、大小写或标点模糊匹配。明确声音归属须关联证据内具有相应标签的片段，不能将 unknown 自动分给邻近人物。

独立清单只列关键事实和关系，不再要求模型逐原文单元填写 substantive/incidental 表；核验只返回补丁、遗漏补充和疑点，不要求逐核对项输出 covered 等判定。程序记录每次提供的原文、负责目标与核对项范围，这只能证明请求范围，不能证明理解正确或没有遗漏。旧诊断中的逐项判定仍可读取，不作为新流程的必填输出。

核验与回读请求已包含原文，声明中的证据只传编号，避免重复携带原文导致输入膨胀。本地成果仍保存完整引文。分层合并也只传局部声明、状态、条件和证据编号，程序仅允许使用父级候选已有的精确证据范围，不允许合并时新造来源；它是整理已有记录的步骤，不能代替原文阅读。新流程随后按完整责任范围对照原稿核验，跨段证据无法放入容量时明确停止。

证据提取与核验同时检查同一事项的前后状态，引用早期说法和后续更正／撤回；不能因早期原句存在就把过时的待完成标签判为已覆盖。仅一方反对不自动等于发起人撤回，未确认的最终状态保留不确定。此规则复用已有请求，不增加调用阶段；语义是否改善仍由固定样例实测。

行动项单独保存，负责人和期限没有证据时留空；建议保留为提议。结构检查只能排除不合法的编号、引文或字段，不能自动证明概括、归属推理和完整性正确。独立核验仍使用用户选定的同一云端模型，不能称为独立评估模型。

整理稿只返回阅读行边界和标点插入锚点。模型选择片段内唯一、逐字匹配的短语，由程序计算字符位置；不要求模型自行数字符。旧偏移格式仍可校验读取，缺失、重复、跨片段短语及同一位置重复插入均被拒绝。程序保留全部原文字符和局部归属，不删短答、不补词、不改数字；跨片段数字及英文词内部的标点插入被拒绝。界面连续排版，明确标出涉及的说话人和未确定归属，可展开逐段查看。Markdown 继续保留逐段归属，原稿与 SRT 保持独立。

## 兼容、恢复与计费

- 在“新建对照任务”选择“会议纪要 · 预览”；“更多对照”提供全文基线、上一版全文理解和旧流程。创建对照不调用模型，不复制成果或账单。
- 新策略使用独立检查点目录和包含策略、协议、原稿、声音边界、校订、模型、强度及预算的身份。成功阶段恢复复用；更改输入或配置不混用结果。
- 长文核验保留负责声明及核对项的全部来源和邻接上下文。概览引用多个远处主题时，不连带导入背景范围内的无关声明；这些声明仍由各自负责批次完整检查，不删原文或跳过核对项。
- 分批核验在开始时固定每条草稿声明的负责范围；补丁修改引用位置后不会把它重新分派给另一批。失败的结构化候选及具体错误保存在本机诊断中，最多保留最近 12 份，不保存模型思考正文或凭据。草稿和证据清单同时报告多处声明错误的位置、引用单元的实际编号范围、所选归属和真实标签，修正反馈最多 1,600 字符，并在完整请求容量估算中预留相应空间；仍受原有一次修正上限约束，不自动猜人或接受错误项。
- 成套成果版本 2 同时发布纪要和原话阅读稿，并记录策略。可选标点操作仅更新同源整理稿及可选 `formatting` 状态，纪要不改写；发布前复查原稿、校订、任务选项和成果代次。新应用读取版本 1/2，拒绝策略冲突或损坏后降级混读；旧成果缺少排版状态照常读取。旧任务与原稿不迁移。
- 补丁按目标类型区分声明、概览和待确认事项。待确认事项使用正文、来源单元和状态，不能混用声明结构；字段错误指出目标和完整格式。需要回听的条目不能由文字核验删除、降级或标为解决。可由文字解决的问题须有逐字来源，再收起显示，审计依据保留。
- 模型配置、缓存统计、价格、用量账本和取消机制共用。新增阶段标签便于区分草稿、证据检查、核验、回读和断句。
- 标点诊断独立保存在 `formatting-run.json` / `formatting-validation.json`，不覆盖纪要运行和核验诊断。build 28 使用 `meeting-reader-v3.12` / `meeting-prompts-v1.6` / `meeting-products-v1.7` 身份；旧版检查点保留但不跨版本混用，重新运行会按当前版本产生新请求，不能当作原版本的无费用继续。暂停的真实对照不会自动恢复。
- 输出耗尽沿用有界扩容，纯思考耗尽不触发无休止切块；中断及失败的已知用量计入账本，未知字段不记为零。

build 29 按用户要求调整当前积算 `deepseek-v4.1-flash` 的会议流程：首轮输出 128K（131,072），耗尽后仅一次扩到 256K（262,144），同样适用于基线和独立标点操作；其他模型、冻结对照、旧录音和 B 站的预算不改。模型列表只返回模型标识，未公布输出／上下文上限，256K 尚未实测服务商支持。拒绝扩容时保留成功阶段并停止；确认的上下文容量仍会收紧输出预算。有效预算进入新版 `meeting-reader-v3.13` 检查点身份，旧成果和检查点不覆盖。思考强度、提示词、单轮请求／Token／时限及失败计费规则保持不变。

## 验收与默认切换

对照固定同一完整版 Large-v3 原稿、模型与高思考强度，另使用 VCSum 116/208 和既有 120 号失败回归。116 虽只有两种数据标签，正文涉及多位嘉宾，只检查文字理解，不据此证明二人分人质量。208 将声音归属统一标为未确定，检查长文本覆盖。公开文本的占位坐标不是真实音频时间，不能用于 ASR、分人或播放质量评价。

关键事实、状态、条件、否定和归属清单须全部通过；已确认重要项保留达到 95% 且不低于最佳基线，并单列重复、无依据新增和修订变坏。它是固定文本清单的门槛，不是整体准确率。模型自评、引用覆盖、篇幅及调用量不能单独推动默认切换。

真实调用通过应用界面启动；检查点、诊断和费用离线汇总。已完成、失败与待完成范围见[会议纪要验收](validation-meeting-v3.md)。未通过全部门槛前不宣称新方案质量更优、不切换默认、不合并或制作正式 Release。
