## 本机已有 Whisper 与加速

用户提示后检查发现：

- Homebrew 已有 `openai-whisper 20250625_3`、`whisper-cpp 1.9.2`；未更新或改写这些安装。
- `~/.cache/whisper/` 已有 `large-v3-turbo.pt`、`small.pt`、`medium.pt`、`base.pt`、`tiny.pt`。
- whisper.cpp 日志识别到 Apple M4 与 Metal backend。MLX 检测 `metalAvailable = true`，默认 GPU 可用。
- 最终复用已有 Turbo 权重。此前启动的重复下载已终止，**只清理本任务产生的未完成下载缓存**。
- Turbo 原权重通过官方 SHA-256 校验：`aff26ae408abcba5fbf8813c21e62b0941638c5f6eebfb145be0c9839262a19a`。
- 本机转换耗时 19.79 秒，生成约 1.61 GB MLX 权重；保留原始 PyTorch 文件。以后直接复用转换结果，无需每次转换或联网下载。

实际转录测量：

该耗时不包括首次模型转换、媒体网络下载和云端总结；峰值是 MLX 分配量，不是整个系统或进程的总内存。音频解码等辅助工作仍可使用 CPU；模型推理选择 MLX GPU，不是纯 CPU 转录。

首次识别结束后，数值校验发现 NumPy 时间戳标量与原生 Python 数值的类型差异。修复为输出边界显式转换浮点数，并加入回归测试。两块实际转录已保存，因此在应用点击“继续处理”时复用 2 / 2 块、重新计算 0 块，约 1.46 秒完成恢复。这个恢复耗时**不算新的推理性能成绩**；原始 70.55 秒记录另存于任务目录。

## 完整性、恢复和界面

- 两份精简稿都覆盖对应原稿的所有来源 ID，顺序检查通过；章节引用均在原稿范围内。
- 原稿不被模型改写。结构校验保证字段与来源关系，不能保证模型每句话的语义准确。
- 核查了先前易出问题的跨段关联：OpenAI API 的“无输出 token 费用”及 Microsoft 诊断系统的宣布者与后文关联。平台字幕版中这些关系保持在相应章节。
- 相邻章节共享大量来源时进行有来源检查的合并，减少分段造成的重复主题；原始章节另存，便于核对。
- 平台字幕与本地转录各自生成独立任务，原稿不会互相覆盖。Whisper 在部分英文专名上更清晰，但仍有识别错误，不把本地转录宣称为必然优于平台字幕。
- 通过重启应用验证任务和笔记持久化；验证展开处理选项后标题、操作区、状态栏可见。
- 通过原生保存面板导出 `build/ui-whisper-notes.md`，逐字节比对与任务保存的 Markdown 相同。
- 真实 Whisper 任务清理了媒体与临时目录，文字、模型与完成的转录检查点保留。另一个平台字幕任务保留的视频不受影响。
- 同一任务使用进程锁；原生应用使用单主窗口。取消测试确认后台进程及其子进程都会结束。
- `codesign --verify --deep --strict build/VideoDHelper.app` 通过（本机临时签名，不等于 Developer ID 公证）。

不含凭证的机器验收数据保存在 `local-data/validation/acceptance-0.2.json`（Git 忽略）。模型请求仅保存用量与结束状态，不保存密钥、请求头或模型推理内容。
