# build 31：减少重复引用坐标，保留失败候选修正

2026-10-31。根据build30两组固定测试均在草稿来源检查停止的结果，修复两者共用的入口。继续录音开发分支与待合并PR，不改ASR、说话人、云模型或新任务默认。

## 本版范围

1. 模型只填写全局唯一的起止片段号，程序计算阅读单元及精确来源。跨单元连续原话按原边界展开，不丢字、不补编号；未提供的片段、错误范围和旧格式中的矛盾坐标仍拒绝。持久化格式与旧成果读取不变。
2. 会议流程的一次格式修正带回原候选正文和具体错误，保留原系统提示与原文，要求只修相关错误。不带回模型思考过程，不增加修正次数。修正请求按实际完整消息重新检查48K工作输入预算及已确认上下文容量；超限明确失败，不裁掉原文或重新生成替代稿。
3. 归属错误只给出本项引用内已有同标签片段的候选编号，由模型根据原话修正；仍禁止将unknown或另一人当作明确归属依据，程序不猜人或自动换人。

保留现有三阶段、独立证据与字段级语义核验。格式修正仍返回完整JSON，这一版没有引入新的通用补丁语言或第三方框架；携带候选帮助减少无关重写，不宣称程序保证模型只改指定内容。B站与冻结context-v2保持原重试消息。

## 社区依据

- [Instructor的重试示例](https://github.com/567-labs/instructor/blob/main/docs/concepts/reask_validation.md)：把失败响应和具体校验错误放回后续请求。本版沿用自己的客户端及有界重试。
- [LangExtract来源定位实现](https://github.com/google/langextract/blob/main/langextract/resolver.py)：把来源定位交给程序。本版使用已有唯一片段编号确定坐标，不引入模糊匹配，也不照搬其算法。

期间不改版、不手动重跑、不追加样本、不重跑ASR或调用可选标点。每项运行至成功或明确失败，然后统一复盘；有有效成品才进行语义评阅。失败保留候选、成功阶段、原因和全部已知用量。即使本轮成功，也不替代重复稳定性和多样本门槛，不自动切换默认legacy。
