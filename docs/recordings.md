# 录音整理

> **适用版本：0.7.0 开发预览。** 本轮尚未合并 `main`、未发布 Release；[已发布 0.6.0 DMG](https://github.com/ShallM/VideoDHelper/releases/tag/v0.6.0) 不含录音功能。自包含预览应用已安装到本机，代码通过 [PR #2](https://github.com/ShallM/VideoDHelper/pull/2) 等待审阅。具体检查范围、实测结果与限制见[录音预览验收](validation-recording-preview.md)。

把手机录音复制到 Mac 后，先在本机提取原话，按需区分两位说话人，核对后再让模型整理对话。首版面向 **普通话、两人对话、5～50 分钟**的常见场景，也允许更短录音；最长 50 分钟。重点支持 M4A、MP3、WAV。

## 一次完整处理

1. **进入录音工作区。** 在左上角功能菜单选择“录音整理”。这会切换整页：项目、最近、未归属、归档和搜索只显示录音任务。B 站视频保留在另一工作区，双方可以使用同名项目。
2. **选择录音。** 点“选择录音”，导入已复制到 Mac 的手机文件。应用保存任务自己的副本，外部原文件不移动、不修改；之后移动外部文件不会使任务副本失效。首版不负责手机同步或实时采集。
3. **选择本地处理方式。** 可用“二人 · 本地区分”或“不区分”，并选择已安装的 Turbo、完整 Large-v3 或 Qwen3-ASR 1.7B。缺少模型时先到“设置 → 语音转文字”下载；[模型管理指南](local-asr-models.md)。点“开始转录”；此时不需要云模型 API，也不产生 LLM 用量。
4. **核对原稿。** 阅读每段原话和说话人标记，点时间回听；可改说话人显示名称，或校订单句文字与说话人。优先检查“不”“不是”、数字、简短应答和重叠讲话。
5. **明确开始 AI 整理。** 配置好模型后，点“整理与总结”。这一步才会把标题、有效原稿及必要中间文字发到配置的模型服务，并可能产生费用。
6. **回听与导出。** 切换“原稿 / 整理对话 / 对话总结”，通过引用时间回到录音；用工具栏导出原稿 TXT / SRT 或两份整理结果的 Markdown。

处理面板可以折叠，资料库继续留在侧栏。切换功能页不会取消当前任务；初版同一时间只执行一个处理任务，避免两边同时加载大模型。

## 三份内容分别保留什么

| 视图 | 内容 |
|---|---|
| 原稿 | 机器识别出的原话、时间及可用说话人标签；人工校订独立保存，机器原稿保留 |
| 整理对话 | 按原话次序去掉口头重复，保留双方的提问、回答、条件和归属，不跨说话人混成一段 |
| 对话总结 | 按实际讨论主题梳理双方观点、问答、明确共识、仍有分歧及待核对处，附来源时间 |

模型不会因为模板需要就强行写出“共识”或“行动项”。“可以考虑”不应变成决定，甲方的建议不应变成乙方的承诺，“嗯”也不自动表示同意。模型保留否定、附带条件和后文更正；这些是生成与核验规则，**并不保证自动结果永远正确**。

短稿整体阅读；长稿先建立全文结构，再整理和回查原文，必要时有界回读。沿用视频总结的来源验证和检查点机制，并将提示词适配为对话，保留说话人边界。当前仍共用章节与整理稿的数据结构，真人录音暴露出话轮碎片、条件遗漏和疑点重复；具体问题及待实现方案见[录音质量复盘与改进计划](recording-quality-plan-2026-10-28.md)，现有流程见[全文理解设计](summarization-v2.md)。

## 说话人、改名与校订

- **A / B 是本段录音内的稳定编号。** 它们不代表性别、身份、角色或真实姓名，也不会用来识别其他录音中的同一个人。
- **不能确定就保留“待确认”。** 声音相似、短应答、远距离录音和同时说话可能导致错误归属。程序不会根据句子含义猜测声纹身份。
- **改显示名称不需要重算。** 可将 A / B 改成便于阅读的称呼；编号保持不变，不重新转录或调用模型。
- **单句校订影响总结依据。** 修改原话或将一句话改归另一位说话人后，已有整理稿与总结会标记需要更新；重新整理会产生新的模型请求，转录结果仍可复用。
- **已完成原稿不会被按钮反复重切。** 分人失败可重试或关闭分人；成功完成、尤其已人工校订后，不用重新转录来覆盖原稿。需要不同的整套识别结果时，可重新导入为独立任务。

校订和重命名在后台处理或归档期间不可用；先取消并等待保存完成，或恢复归档任务，再修改。

## 本地引擎与首次下载

| 阶段 | 引擎与计算路径 | 首次准备 |
|---|---|---|
| 提取原话 | MLX Whisper / Qwen3-ASR，Apple Silicon Metal GPU | 在设置中主动下载，Qwen 连同时间对齐组件管理；应用不含权重 |
| 可选二人分离 | SpeakerKit / Core ML，CPU 与 Apple Neural Engine 混合 | macOS 15+ 模型文件约 11.24 MB；macOS 14 约 15.47 MB |
| 整理与总结 | 用户配置的语言模型 API | 需配置地址、模型和凭据；按平台实际用量计费 |

本地转录不可使用 Metal 时会停止并提示，不自动改成纯 CPU 转录。**SpeakerKit 的分人不是全 GPU 路径：语音分割与聚类使用 CPU，声纹嵌入阶段配置 CPU / Neural Engine。** Core ML 的实际算子调度由系统决定，不能据此承诺全部嵌入计算都在 ANE。

分人模型与 Whisper 权重独立缓存。上表体积是所需模型文件大小，不是安装包大小、内存占用或完整编译缓存大小；首次模型下载需要联网，后续可复用本机缓存。选择“不区分”可跳过 SpeakerKit 准备与推理。

固定来源、revision、模型大小及计算配置见[SpeakerKit 组件清单](../packaging/speakerkit.json)；代码与模型许可不同，见[第三方说明](../THIRD_PARTY_NOTICES.md)和[模型声明](licenses/speakerkit-models-NOTICE.txt)。

### 方案依据

转录和分人分别处理，时间对齐后才生成文字总结；这一分阶段思路参考 [WhisperX](https://github.com/m-bain/whisperX)，本项目继续使用 MLX 转录，并实际集成 [SpeakerKit OSS](https://github.com/argmaxinc/argmax-oss-swift#speakerkit)，没有整套移植 WhisperX。默认编号、整体改名和逐句校正的交互参考 [MacWhisper 的说话人识别说明](https://docs.macwhisper.com/article/32-automatic-speaker-recognition-in-macwhisper)。这些参考不能替代本机样本验收，也不代表效果与参考产品相同。

## 思考强度、用量与费用

思考强度保存在每个模型的配置中，B 站和录音功能页共用这些模型设置。DeepSeek V4 提供服务商默认、低、高、最高；通用兼容模型另有中档。服务商默认不发送强度参数，不代表关闭思考。

改变强度只作用于下一次处理，会影响对应总结检查点的复用。连接测试本身会产生用量；测试成功只说明接口接受了请求，不证明积算等代理实际执行了所选档位，也不表示更高档必然更准确。具体选项见[模型思考强度](user-guide.md#reasoning-effort)。

输出预算超过 32,768 Tokens 时，网络等待上限为 1800 秒；高 / 最高强度或预算至少 8192 Tokens 的其他请求为 600 秒，较小请求为 150 秒，均按本轮剩余时限收紧。这不是整份录音的完成时间承诺。超时后不会自动重复提交：服务端可能仍在生成，重复请求可能另行计费。已完成检查点保留，可稍后继续；未返回的用量不记成零。高强度也可能先耗尽输出额度，截断结果不会作为完整笔记保存。

核验阶段有界扩容：高 / 最高依次尝试 16,384、32,768、131,072 输出 Tokens，其他档位的正文截断沿用 24,576 上限。高强度即使只返回思考、没有正文，也允许继续到下一档；达到最终上限仍失败则停止。已知不足的预算与成功结果均保存，恢复时不会再次支付同一失败预算或已完成请求。扩容属于新增请求，会记录对应用量；推理 Tokens 已包含在输出 Tokens 中。高 / 最高强度的整轮默认边界为 80 次请求、100 万累计已返回 Tokens 和 2 小时；其他档位为 80 次、50 万和 30 分钟。累计用量在发起下一次请求前检查，最后一次响应可能使其超过阈值；不是服务商账单硬限额。

全局用量页支持来源筛选：全部、B站视频、录音整理、连接测试。纯本地转录与分人不产生 LLM Tokens。整理阶段沿用输入、输出、推理、缓存命中统计和手填单价换算；它是本机估算，不是服务商账单。取消中的云请求仍可能已经被计费。

## 失败、取消与恢复

| 中断位置 | 保留内容与下一步 |
|---|---|
| 模型准备 | 保留已取得的模型缓存；检查连接后重试，或关闭可选分人 |
| 本地 ASR 转录 | 保留任务音频和已完成的窗口检查点；继续处理时复用可验证的窗口 |
| SpeakerKit 分人 | 已完成 ASR 原稿保留；可重试分人或改为“不区分”。未完成分人会重跑该阶段，不承诺从内部帧位置继续 |
| AI 整理 / 核验 | 保留有效原稿、人工校订与已完成检查点；确认模型配置后重试 |
| 人工修改原稿 | 原稿副本保留，旧总结提示需要更新；重新整理使用修订后的内容，不能套用旧来源缓存 |

“取消”会等待当前阶段释放资源和保存已完成内容。原件仍属于当前任务，不套用视频页“完成后清理媒体”的选项。归档只收起任务；删除将任务目录连同录音副本移入 macOS 废纸篓，不删除外部原文件、其他任务或模型。删除也不会撤销已发生的模型用量。

两个资料库也在磁盘上分开：B 站任务使用 `tasks/<UUID>/`，录音任务使用 `recording-tasks/<UUID>/`，各有独立的项目目录文件。较旧应用只读取原有视频目录，不会把录音任务误当作视频；应用回退包仍不等于个人数据备份。

## 范围与验证边界

首版不提供自动性别判断、跨录音声纹库、多人会议识别、实时录音、手机同步或声道身份推断。说话人标签需要依据实际音频检查；自动转录也可能听错专名、数字和否定。

开发期间已用自造合成普通话样本完成 5 分钟本地流程与 50 分钟音频压力、中断恢复检查。**重复合成的 50 分钟样本不等于真实 50 分钟对话验收，合成轮次匹配不等于真人准确率。** 真实手机录音的具体结果与修复记录见[录音预览验收](validation-recording-preview.md)。原稿覆盖、引用合法和整轮完成不等于语义零遗漏；声音与文字仍须结合回听核对，尤其是专业术语、短应答、否定和共识归属。
