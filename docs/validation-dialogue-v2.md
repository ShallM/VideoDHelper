# 录音文字理解 · 0.7.0 build 16 验收

本轮在 `codex/recording-workspace` 实现录音的「全文对话理解」，保留旧流程和独立对照入口。正式 Release 仍为 0.6.0；本页记录开发预览验收，不代表已合并或发行。

## 变化与验收边界

- 以可读上下文承载局部 A / B / 归属未确定片段，原稿、时间与说话人标记保持可追查。
- 总结全文优先；整理稿单独安排阅读行，只对必要文字提交稀疏编辑，未改部分由程序逐字复制。
- 核验直接读取来源，按负责范围检查遗漏与证据；最多两轮、共六个具体风险回读，使用稳定编号修补，最后不再整稿重写。
- 结果以单一原子文件发布，旧任务兼容读取；已有检查点、用量、取消恢复及模型设置继续共用。

来源编号覆盖与结构合法不证明语义准确。原机器稿不是人工逐字金标准；本轮不计算 CER / DER，也不据此对三个 ASR 型号排名。

## 样本与方法

真实样本为用户提供的 21 分 42 秒普通话二人录音，固定同一历史 Turbo 原稿、说话人结果与云端模型 `deepseek-v4.1-flash` 的「高」强度。原稿 1,060 个带归属片段、6,139 字符，旧阅读器得到 504 段，新适配层得到 21 个阅读单元。正文完整保留，附编号的传输文字由 17,536 减为 13,137 字符，减少约 25%。这只是表示成本改善，不是 Token 精确压缩率或识别准确率。

另保留同一录音的 Large-v3 / Qwen 原稿作适配回归，以及独立的 [VCSum 官方中文会议文本](https://github.com/hahahawu/VCSum) 120 号样本（revision `8e51d72e4e6f3af4074fd5b260b6f6d2e75e86c7`）。该保留文本 5,175 字符、26 段，25 段为同一说话人，不能视为均衡二人手机录音。它没有音频；本地序号时间仅供格式处理，不能用于时间跳转或 ASR 验收。

在评新稿前冻结了 38 项带来源核对候选，并由与生成调用分开的模型辅助审阅旧稿及新稿。候选未经用户听音确认，审阅结果不是人工金标准；其中 20 项旧稿已保留的重要细节另作严格回归诊断。旧高强度总结约 7,368 字符，新稿更短，二者没有按相同篇幅控制，因此不将项目覆盖比例写成准确率或整体质量排名。区分无支持的新事实、改变含义的条件遗漏、可接受的细节压缩。

私人音频、原稿、核对清单及逐条错误证据仅留本机忽略目录；公开[聚合记录](research-data/dialogue-v2-validation.json)只包含数量、耗时、用量与运行状态。

## 开发中复现并修复的问题

| 实际问题 | 处理 |
|---|---|
| 要求模型重写全部细碎片段，容易合并归属、改掉短答，且输出昂贵 | 改为代码持有全部源片段；模型只返回行边界和稀疏文字编辑，所有编号恰好覆盖一次 |
| 单个或两个字符被当口头语删掉 | 此类片段只允许插入标点，不能删字、改字、调序或删除原标点 |
| 加标点被误计为内容扩写 | 扩写预算排除标点与空白，实际原文和成品仍保持原样 |
| 展示片段重新编号导致核验错对原文 | 目标编号固定到原片段，并明确提供来源 part 编号 |
| 接口返回形式不合法的 JSON | 对已实测支持的服务与模型启用 JSON 对象模式；其他服务不擅自启用，仍有一次结构修复 |
| 全部内容一起核验仍漏条件、添加不完整范围的结论 | 将一轮核验分配较小负责范围，继续提供全文用于指代和范围检查；结果仍需语义验收 |
| 核验内部编号可能进入待确认正文 | 检查读者文本中的内部编号；原文真正存在的同名代码变量保留 |
| 取消或写文件中断可混用两代成果 | 先原子发布 notes 与 condensed 的共同 generation，再写兼容副本；读取方不混合世代 |

早期协议的失败与停止记录保留，不把它们统计成最终版本成功率。被主动停止的在途调用保留未知用量；字段缺失不按零费用处理。

## 最终协议实测

最终协议固定为 `dialogue-prompts-v2.4`，没有在下列各次之间修改提示词或按成品好坏挑选结果。高强度本身有输出波动；下表包括失败、格式修复和预算扩容的实际请求。

| 样本 / 运行 | 结果 | 耗时 | HTTP 请求 | 输入 / 其中缓存 Tokens | 输出 Tokens（含推理） | 已知费用（元） |
|---|---|---:|---:|---:|---:|---:|
| 真实录音 · 第一次 | 完成，87 行整理稿 | 909.603 秒 | 12 | 74,596 / 17,280 | 185,572 | 1.59989920 |
| 相同输入 · 第二次 | 完成，86 行整理稿 | 802.436 秒 | 12 | 74,157 / 23,552 | 141,552 | 1.23456808 |
| 相同输入 · 中断恢复 | 完成，117 行整理稿 | 累计 1,209.923 秒 | 15 | 99,829 / 46,080 | 241,868 | 2.04428520 |
| 独立 VCSum 文本 | 校验失败，未发布成果 | 287.482 秒 | 5 | 20,899 / 4,352 | 58,501 | 0.50127608 |
| 合成条件 / 数字样例 | 完成，9 行整理稿 | 122.868 秒 | 3 | 4,487 / 2,560 | 27,601 | 0.22476440 |

费用按已配置的每百万 Tokens 人民币单价：未缓存输入 2、缓存输入 0.04、输出 8 计算。输入总量含缓存，推理包含在输出中，不重复收费。它是应用依据返回用量的估算，不代替服务商账单。开发中较早协议另有 74 次请求，已知费用 8.84034248 元、6 次费用无法完整确定；它们单独保留在聚合记录，不与最终协议混成成功率。

恢复组在完成第一批整理后、下一次请求前主动中断，先用 218.379 秒；恢复用 991.544 秒，合计排除人工暂停时间。恢复读取两个已有成功检查点，其内容哈希和修改时间不变，后续发生一次输出扩容与一次定向回读。完成后在复制的检查点上禁止 HTTP 并重放：**0.042 秒、11 次成功命中、1 次已知额度限制命中、0 个新请求、0 新 Tokens**，输出除本轮计量字段外一致。整个恢复组累计 15 次实际请求；聚合记录中的末次执行 `requests=12` 不包含中断前的 3 次。

前两次真实结果都由 21 个完整阅读单元直接生成总结，核验分为四个负责批次并保留全文背景；本次均未触发额外定向回读。稳定片段覆盖、字符范围与结构化说话人检查通过。整理稿从旧稿 496 行降到 87 / 86 行，没有删除短答来凑行数；这证明展示与输入表示改善，不能推导为语义更准确。

**语义门槛未通过，因此新录音仍默认旧流程。** 两次分别出现把局部机构要求泛化、把已具备材料写成待准备、遗漏条件或现有资源，以及核验新增不准确算术措辞等问题。部分条件确实被核验补回，但仍有修复后新增错误；不能只选某次较好成品宣布胜出。VCSum 在一次结构修复后仍把内部编号写入读者正文，被守卫拒绝；无最终 notes 或成套成果，保留已完成检查点。

恢复组同样出现范围泛化；整理稿的一处核验编辑还重复了相邻归属未确定片段中的词，放入确定说话人的片段。因此来源 ID / span / speaker 字段完整，并不证明生成正文完全无损或叙述归属正确。那一次回读没有修正正文，而是把模糊原话留待听音，最终仍留下近重复疑点。只把它计为回读与恢复路径完成，不计为成功解决语义问题；当前去重基于类型、来源和字面身份，不承诺语义近似去重。

合成样例保留数字、小数、否定、行动前提、撤回与未知费用，整理正文逐字保留；仍有把“文字归属未确定”写得像“文字听不清”的轻微问题。该样例核验没有改动，不能把正确内容归功于修复效果，也不能替代真实录音验收。

本轮到此冻结协议，保留显式预览以收集体验，不继续围绕同一私人录音叠加提示词。后续先补独立人工参考，分别诊断原稿错误、整理改写与总结推断，再决定默认方案。
