# 数据与隐私

任务与转录在本机管理。AI 总结需要将文字发送到你选择的模型服务，因此它不是完全离线应用。

本文标注的录音与双工作区行为属于 **0.7.0 开发预览，尚未合并或发布**；当前 0.6.0 DMG 只提供原视频流程。

| 数据 | 去向 |
|---|---|
| 视频链接、B 站会话 | 用于从 B 站读取用户有权访问的内容；会话保存在本机 |
| 音频、视频 | 本机下载与处理，不发送给总结模型 |
| Whisper 模型 | 本机复用 / 转换，缺少时从对应模型仓库下载 |
| 手机录音原件（开发预览） | 复制到当前任务的 `source/`，本地转录及回放；外部原文件不移动、不修改 |
| SpeakerKit 模型（开发预览） | 可选分人阶段从固定模型来源下载并缓存；不会向模型仓库上传录音 |
| 标题、原稿、来源编号与中间笔记 | 发送至配置的模型服务完成整理与核验 |
| 录音中的姓名与私人信息（开发预览） | 如果这些内容出现在任务标题或有效原话中，点击“整理与总结”时也会随文字发往所选服务 |
| 任务、检查点、价格和用量 | 保存在本机 Application Support |

目录为 `~/Library/Application Support/VideoDHelper/`：

```text
preferences.json          通用设置、模型、价格与 API Key
bilibili-cookies.txt       B 站会话
library.json              B 站项目、任务归属与归档状态
library-recording.json    录音项目、任务归属与归档状态（开发预览）
tasks/<UUID>/             B 站原稿、笔记、媒体、检查点
recording-tasks/<UUID>/   录音副本、原稿、校订、总结、检查点（开发预览）
models/                   本地转录模型；分人模型有独立缓存
usage/events/<UUID>.json   每次 HTTP 尝试的状态与计量
usage/task-history/       删除任务前保留的历史计量（待发布）
```

API Key 当前保存在权限 `0600` 的私有配置文件，尚未使用 Keychain。用量记录不包含密钥、提示词或响应正文；任务检查点包含文字，不能把整个任务目录当成可公开日志。

录音任务的音频副本、机器 ASR、自动分人结果和人工修订分开保存：`source/` 是音频副本，`asr-transcript.json` 保留词时间，`transcript.json` 是机器原稿，`transcript-edits.json` 保存人工修订，`speakers.json` 保存显示名称。A / B 是单个任务内的编号，不建立跨录音身份库，不推断性别。

录音流程先在本地完成转录及可选分人；这一步不要求云模型配置，不发送录音或原稿给总结服务。用户明确点击“整理与总结”后才发送标题、有效原稿、稳定说话人标记和必要中间笔记。声音始终留在本地；使用模型服务后的数据保留方式取决于该服务的政策。

关闭媒体保留只在三份文字保存后清理本任务媒体。取消或失败保留恢复资料，移除项目不删除任务。分享导出内容前，请检查文字与来源是否适合公开。

上面的媒体保留开关属于视频页。录音任务保留自己的音频副本供回听和恢复；取消、分人失败和整理完成都不会自动删除这个副本。归档保留全部资料；删除录音任务时，仅把当前任务目录与副本移入废纸篓，不触及手机或 Mac 上另行保存的原文件。人工校订和机器原稿也会随任务目录一同移动。

开发分支新增的归档与删除功能尚未包含在 0.6.0 DMG 中。归档只改变列表状态，不清理任务内容；删除将任务目录移入 macOS 废纸篓。历史用量、价格快照和用于辨认记录的任务标题独立保留，不包含原稿或笔记正文。删除任务不会删除另行导出的文件。恢复方法见[使用指南](user-guide.md#任务归档与删除待发布)。

`.env.example` 只有占位配置。实际 `.env`、Cookie、媒体、模型、个人任务和原始验证全文均不提交。公开研究数据只保留指标、内容核对条目与结论；完整复测需要本机资料。
