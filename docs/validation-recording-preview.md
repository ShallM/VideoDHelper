# 录音工作区开发预览验收

日期：2026-10-28。适用版本：**0.7.0 开发预览**，分支 `codex/recording-workspace`。本报告记录已经完成的检查及尚未完成的验证。**维护者本机已更新到 0.7.0 / 构建 14 自包含预览版，尚未合并或发布 Release**。当前正式安装包仍为 [0.6.0](https://github.com/ShallM/VideoDHelper/releases/tag/v0.6.0)。

## 首轮合成样本、环境与范围

本地样本为自编普通话二人对话，使用 macOS Tingting / Eddy 语音合成，95.63 秒母样重复为 5 分钟和 50 分钟 WAV。实际读取、转录和区分说话人，未用虚构时长替代音频运行。任务、项目、设置及模型调用记录放在隔离的数据目录，没有使用私人录音或改动真实任务。

验证设备为 **Apple M4、24 GiB 内存、macOS 26.6.2**。Whisper Turbo 使用 MLX / Metal；SpeakerKit 配置为语音分割 CPU、声纹嵌入 Core ML CPU / Neural Engine、聚类 CPU。没有逐算子测量硬件调度，也没有在 macOS 14 真机复测。

**重复合成音频适合验证长时间轴、资源占用和中断恢复，不能代表真实手机录音、重叠讲话或自然对话准确率。** 一次压力测试的峰值与进程退出检查，也不能证明不存在所有内存泄漏。

## 离线自动检查

本轮 **87 项 Python 测试、66 项 Swift 测试通过**。使用临时数据和模拟接口，覆盖录音与视频的物理目录及资料库隔离、旧数据兼容、校订与任务锁、归档删除恢复、来源与说话人约束、思考强度请求、用量持久化和检查点复用。它们不代替模型语义质量或安装副本的实际验收。

复测入口见[构建说明](building.md#测试)。

以合成参考时间核对已覆盖词，1068 个归属正确、0 个已知错归、22 个未确定、2 个不在已知参考范围。未确定多为话轮开头短词，未强猜归属。

资源记录分别为：worker 峰值 RSS **896,172,032 字节**，`time` 报告的峰值 memory footprint **4,536,797,800 字节**，MLX 峰值 **2,233,323,410 字节**。这些口径不同，不能相加。

## 本地 50 分钟压力与中断恢复

输入为 3000 秒、96,000,044 字节的真实 WAV。全程只运行本地转录及分人，没有 LLM 请求或用量事件。

| 阶段 | 耗时 | 核对结果 |
| --- | ---: | --- |
| 首窗完成后取消 | 29.412 秒 | 已保存 237.664 秒首窗；发送 SIGTERM 后 2.075 秒退出，任务为 `cancelled` |
| 恢复到全部原稿及说话人对齐 | 313.169 秒 | 运行记录确认复用 1 窗、新算 12 窗；SpeakerKit 阶段约 15.5 秒 |
| 完成后再次执行相同请求 | 1.025 秒 | 没有子进程，全部检查点内容及修改时间不变 |

含中断与恢复合计 **342.581 秒，约 5 分 43 秒、8.76 倍实时速度**。这不是未经中断的单次冷启动耗时。MLX 峰值为 **2,290,814,866 字节**，进程树 RSS 采样峰值为 **1,859,977,216 字节**。

13 个 ASR 窗口的 12 个内部边界都匹配到停顿，没有使用固定边界回退。恢复后首窗检查点的内容及修改时间保持不变；三次运行结束均没有进程组残留。原稿编号连续、时间非递减且在音频范围内，末段结束于 2999.882 秒。

最终有 1303 段：A 574、B 478、未确定 251。未确定主要是换人边界附近的一两个字，占总文字约 **2.52%**；段数比例不能当作识别错误率。原音频、SRT 和文字导出均保留。

SpeakerKit 另有独立组件测试：同一 50 分钟样本的缓存准备、加载与分人共 16.606 秒；分人过程中 SIGTERM 在 0.011 秒内退出且未覆盖旧结果。这是 helper 单独测量，不能替代或叠加到上表的完整 worker 耗时。

## 首轮合成稿的真实模型请求与质量边界

调用积算平台 `deepseek-v4.1-flash`，只发送合成录音转录文字，没有上传音频。共 **6 次实际 HTTP 请求**，每次显式发送 `reasoning_effort`。没有通过服务端证据确认各档位的实际思考策略；接口接受 `high` / `max` 不等于验证其质量或性能优于 `low`。

| 请求 | 请求设置 | 输入 Token | 输出 Token | 其中推理 Token | 结果 | 耗时 |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| 1 | low，whole，人为上限 6000 | 1831 | 6000 | 6000 | `length`，没有正文 | 103.741 秒 |
| 2 | low，plan，人为上限 6000 | 1901 | 6000 | 5740 | `length` | 45.881 秒 |
| 3 | low，半段 plan，人为上限 6000 | 1285 | 6000 | 4200 | `length` | 40.982 秒 |
| 4 | high，上限 1000，极短条件问答 | 90 | 208 | 184 | `stop`，JSON 可读 | 6.121 秒 |
| 5 | max，上限 1000，同一极短问答 | 90 | 287 | 262 | `stop`，JSON 可读 | 1.725 秒 |
| 6 | low，正常 whole 上限 12288，仅一次 HTTP | 1831 | 7844 | 5122 | `stop`，完整 JSON；一处引用未升序 | 68.161 秒 |

合计输入 **7028**、输出 **26339**、总量 **33367 Tokens**。推理 **21508 Tokens 已包含在输出中**，不能重复计费。第 2 次返回缓存输入 192 Tokens，其余未返回缓存数，不能当成 0；单价未配置，所以不估算金额。

前三次的人为上限 6000 低于正常 whole 的 12288，不能据此认定默认预算无法完成。无正文的推理耗尽输出额度，也不说明原文需要不断拆小。本轮已增加明确停止及检查点保护，遇到这种情况不继续自动拆分调用；相应路径通过离线测试。

正常 whole 使用 50 段紧凑原稿，返回 4 个主题章节、8 条关键点、50 条整理对话，覆盖全部 50 段且没有跨说话人合并。首次生产结构检查只因一处引用数组 `[3,21,35,22]` 未升序失败；单请求限制阻止了第二次自动修复。**离线仅将数组排序为 `[3,21,22,35]` 后结构检查通过，没有修改模型正文来制造通过结果。**

人工阅读未发现主题级遗漏，但仍发现三类问题：概览把仅有单方依据的“共识”扩大成双方认可；正文出现内部 `p` 编号；说话人使用裸 `A / B` 而非约定标签。当前已加强共识归属、正文引用格式及稳定说话人标签规则，并补充展示与导出联动检查。**这一轮的第 6 次没有运行完整 review / 核验阶段，不能据此宣称默认生产总结流程或语义质量全部验收通过。后续使用真人手机录音的结果单独记录如下。**

### 实际模型调用暴露的问题

- 当前模型为 `deepseek-v4.1-flash`。高强度规划和核验会持续超过旧有 150 秒等待；已将高 / 最高强度及输出预算至少 8192 Tokens 的请求放宽到 600 秒，并限制在本轮剩余时限内。
- 网络超时不能说明平台未处理请求。现在停止自动重复提交并保留未知用量，避免服务端尚未结束时再次提交同一请求。超时后仍可由用户继续，新的请求单独计量。
- 高强度完成了全文结构与 11 个章节，但核验先耗尽 16K 输出预算。增加一次 32K 有界扩容后，首段核验返回有效正文，并补充遗漏细节及修正归属；中段核验在 32K 仍只返回思考、没有正文，流程明确停止。**不能把高强度这一轮计为完整总结成功，也没有继续提高预算反复调用。**
- 整理对话曾把很短的原话扩写成“未形成完整信息”等解释，已改为保留直接话语、人称与问句，并禁止这类旁白；原始转录始终保留。
- Markdown 导出修复章节标题未使用说话人显示名称的问题；正文、标题和界面保持联动。

随后仅在测试请求中改用低强度作对照，个人模型配置仍保留高强度。低强度首次已完成全文结构与 13 个章节，在核验等待超时后停止；修复等待规则后复用这些检查点继续，未重复转录或生成章节。完整结果如下，未手工改写模型正文来制造通过结果。

| 低强度对照 | 实测结果 |
| --- | --- |
| 首次运行至超时 | 724.210 秒，完成规划与 13 章；包含一次 150.249 秒超时 |
| 修复后恢复并完成 | 815.248 秒，复用 14 个检查点、新增 11 次请求 |
| 两次运行累计 | 1539.458 秒，约 25 分 39 秒；包含超时，不含人工修复与重建等待 |
| 最终内容 | 13 章、59 条章节要点、8 条关键点、15 条待确认内容 |
| 原文覆盖核验 | 504 / 504 紧凑段落，3 段全文核验、6 次定向回读、9 处修正 |
| 整理对话 | 496 条，1060 段来源恰好覆盖一次且顺序不变，未跨说话人合并 |
| 完成后再次执行 | 1.026 秒，0 新请求，检查点 SHA-256 和修改时间全部不变 |

人工按机器原稿核对六个主要话题，主题范围保留；条件、问答和归属有来源。结构检查没有发现内部段落编号泄露或导出残留裸说话人标签。但整理对话共 6385 字符，原稿为 6139 字符，**仍略长于原稿，不能称为明显精简**；专业词同音误识仍会进入结果，15 条待确认项中包括 2 条回读预算内未确认关系，语义质量仍需用户回听。

低强度共 26 次请求（25 次返回、1 次超时未知），已知输入 143743、输出 163066，其中推理 138806、缓存输入 66304 Tokens。按测试时已配置单价，21 次可计价请求小计约 CNY 1.185750；另 5 次缺少用量或缓存数据，不能记为免费，**该金额不是完整费用**。这不是正常单轮性能基准：它包含开发期间的失败与恢复，13 分 35 秒也只是恢复段耗时。

用户提供的服务商账单与低强度恢复阶段的 **11 条请求逐条匹配**：未缓存输入 40429、缓存输入 28992、输出 62338，合计 131759 Tokens。输入 2 / 缓存 0.04 / 输出 8 元每百万 Tokens 的计价合计 **CNY 0.58072168**，与平台金额一致；排除了一条其他应用的请求。这验证的是这一批已知请求的计量，不能据此补齐其他超时或未返回缓存用量的历史请求。

用户随后要求继续提高高强度预算探索。核验现在可在已知 16K / 32K 不足后尝试 128K；复用既有高强度规划与章节，低强度成果另存作对照。 首个128K请求在同一失败位置成功返回正文，实际输入11030、输出22504，其中推理22107 Tokens，用时331.834秒；平台接受该上限。之前32K耗尽、本次不到32K完成，说明生成长度有波动，不能据此认定固定最低额度。

高强度随后完整完成：**11章、59条章节要点、8条关键点、19条待确认**；核验覆盖504/504段，6次定向回读。全文核验与回读累计16处修正、2条补充；改动数量不是准确率分数。此次恢复用时1060.432秒，复用15个成功检查点、跳过4个已知不足预算，新增10次请求（输入67111、输出92680，其中推理87674）。这些数字不包含早先已支付的规划、章节和失败请求，不能当成冷启动全流程的成本或耗时。完成后重放1.032秒，零新请求，已完成检查点内容与修改时间不变。

高强度整理对话496条、6361字符，来源1060段全部覆盖、顺序与说话人边界合法；仍略长于6139字符原稿。人工阅读发现高强度对一处含混转录词作出了来源不能充分支持的解释，且若干疑点重复；低强度在该处更接近原转录。**提高额度解决了流程停住的问题，并没有证明高强度普遍优于低强度，更不等于语义零错误。** 原始结果不手工修饰，具体内容仅记入本机私有质量报告，供回听校订。

截至本轮结束，此录音开发验证累计64次请求，59次返回、5次用量未知；已知输入374777、输出537817，其中推理471303，已知缓存139776 Tokens。50次具备完整价格与用量依据，小计约CNY 3.840505；14次暂不可计价（包括5次未知用量及9次缺少缓存字段），不是完整账单。应用录音用量页已逐项核对；缓存命中率44.8%仅按返回完整缓存明细的同批输入计算，不把缺失缓存字段当0。

## 启停与内存观察

隔离开发应用正常退出后进程消失；重新打开恢复录音页、任务、说话人名称、校订及模型强度。两轮各 6 次工作区切换均显示正确资料库，没有任务混入。

`leaks` 对非调试签名进程有只读内存限制，因此结果不能作为完整泄漏证明。新进程基线报告 359 个 / 17,472 字节；6 次切换及辅助功能采样后为 1190 个 / 57,632 字节；仅追加 24 次辅助功能读取、不做界面操作后又增至 1404 个 / 67,872 字节。可见根对象集中于 AppKit 工具栏辅助功能 action、数组和 AX observer，源码审阅未发现新的明确强引用环；**读取界面的验收工具本身也影响统计，尚不能排除小量泄漏，不能宣称“零泄漏”**。长转录 MLX 峰值未随窗口数持续增长，完成与取消后进程均已退出。正式发布前仍需补充可调试分配栈与真实日常使用观察。
